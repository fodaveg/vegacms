# Caddy active apply: local engine DRAFT

OperationId `7a2f1dce-315c-4861-b35d-0c82e38c3231`. This directory contains a concrete four-file apply/rollback engine, but no SSH entry point, approval, runtime adapter, final validation receipt or final logger transformer. It cannot be applied to production in its current state. The old DRAFT operation `4e0ed8b8-bd8b-48e7-9408-ec146c3e40ec` is superseded only locally; no remote attempt took place.

The engine accepts a `FINAL_VALIDATED` package binding a final validation receipt, projection, reviewed transformer SHA256, four source and postimage SHA256 values, Compose guards, and pinned runtime identity. DRAFT/PENDING inputs stop in `require_ready()` before a backend or file access. The transformer must contain `build_postimages(originals)` and its exact source bytes must match the SHA in the successful validation receipt. This leaves the disputed global logger syntax to a future reviewed transformer; the engine does not assume `log default` is present or construct another logger. The three CSP/panel patches and fourth logger change must all be in that transformer and its validated postimages.

`Engine` needs explicit callbacks for runtime observation, same-image isolated adapt/validate, reload of the same existing Caddy ID, and finite public smoke. The callbacks are **not yet provided**. Their outputs are checked, not trusted as plain booleans. Observation must prove pinned IDs/Compose, exact directory bind mount, PID1 command/config path, admin availability, unchanged approved import closure, unchanged referenced environment values, and sink proof. No module reads Env or logs itself. Validation must return the same image/consumer and exact four-file tree SHA, scope proof, and zero adapt/validate exits. Reload must return zero and same ID/PID1, followed by another runtime guard. Smoke must report headers, panel block, assets, API, peers, and controlled logger marker absence plus positive control. A sink/logger inspection needs its own explicitly reviewed read scope; these callbacks cannot be filled by guesswork.

Once inputs and authority exist, the engine reads only four fixed source paths through no-follow directory FDs, checks regular-file identity and hashes, computes the four exact postimages in RAM, and validates them before any source write. It creates an exclusive backup directory outside the source tree (base 0700, owned by the executor) and four 0600 backup files. It journals IDs, source/post hashes, installed set and next effect before each replacement/reload. Each staged file is exclusive and fsynced in the target directory; every source and runtime guard is rechecked before every replacement. Replacement is atomic within the pinned parent FD, with no wildcard writes. Installed files are validated again in an isolated copy before one reload. Unknown reload or transport outcome stops without replay or blind rollback.

After a deterministic post-install validation or smoke failure, rollback checks full CAS/runtime again, restores only own changed files from the backup, validates the original four-file tree, and reloads once only if this operation successfully reloaded. Any foreign change or uncertain effect stops and preserves backup/journal. No data volume, PocketBase database, other Caddyfile/import or container is restored/recreated. The returned projection is a fixed phase/failure enum and booleans; private source bytes and values stay server-local. The journal is private and contains only reviewed IDs and hashes.

Local tests: `python3 -B .verification/caddy-active-apply-20261015/test_apply_engine.py` (12 tests, `apply-tests.log`). These use synthetic four-file fixtures and callbacks. They prove draft rejection, transformer seal, no-follow symlink rejection, sink/env preconditions, same-image proof requirement, backup mode, CAS on a foreign edit, deterministic rollback, no retry on uncertain reload, and finite projection. They do **not** accredit Caddy runtime, actual mounts, admin, sink, deployment, or public smoke.

For a future FINAL candidate, the release owner must supply a reviewed four-delta transformer and successful exact validation receipt, pin the full package and runtime adapter, inspect the diff/tests, obtain application/reload and sink-read authority, then run a separate one-shot remote wrapper. This DRAFT has no executable remote wrapper and no approval file. `preflight.py` verifies its local seal and always reports `DRAFT_BLOCKED`.

## Transporte: APTO en los dos SHA señalados

- Receive verifica localmente tamaño/hash antes de abrir SSH; el servidor exige espacio vigente tanto `/srv` como DockerRootDir, crea ROOT privado y recibe con O_EXCL/no-follow, tamaño máximo, hash y sellado sin overwrite. Son siete artefactos conocidos; ninguno lleva `.env` de producción.
- Load vuelve a verificar archivo y cadena de todos los blobs antes de importar. Manifiesto OCI → config SHA → plataforma Linux/amd64 → capas tar sin comprimir con digest de bytes **igual a diffID**, orden y correspondencia con Docker manifest exactos. El marcador O_EXCL impide segundo intento automático; la consulta de ausencia de tag requiere Docker exit0. Una falla puede dejar imagen/residuo cargado y exige inventario RO, no reload automático.
- El server ID se compara con OCI efectivo y Descriptor, capas y plataforma, sin Config.Env. Preview esperado `sha256:fbfa35eec344c70c21f802a82ed91dfcb8441c5c4a0ab022042eefe4ae366422`; builder `sha256:8e55820698768191ca8b446f41112bf7e861a2c2373b415661f16f4472a446cb`. Config IDs `4678…`/`92b5…` se mantienen diferenciados.
- SSH no imprime stderr y stdout solo se guarda si cumple el esquema cerrado y el exit code previsto. Fuente remota validada y enviada desde el mismo buffer; salida JSON nueva0600. No comandos Caddy, Compose, volúmenes live, secretos, logs ni stop/start en este par.
- APTO es estático para receive/load guardados, no una afirmación de importación realizada o éxito futuro. Raíz conserva autoridad, presupuesto vigente y runtime approval. No autoriza ejecutar el corte/lector con hallazgos pendientes.

## Hallazgos anteriores cerrados y contexto relevante

- **IDs locales incorrectos:** cerrado en ejecución remota. El receipt de cadena local contiene preview8 capas y builder6; `compressedLayers==diffIds` para ambos archives actuales de capas tar. El projector local valida digests de los blobs y enlaces; el transporte además exige el mediaType raw y digest==diffID, por lo que no confía solo en `chainVerified` del projector o en etiquetas. No he vuelto a hashear los400MB ni ejecutado el projector; se reutilizan los recibos de archivos sellados y se revisa la verificación antes de LOAD.
- **Salida arbitraria:** cerrado por wrappers/payloads Python. Errores se convierten en clases fijas STOP; stdout/stderr de Docker/Compose/systemctl/publisher permanecen RAM VPS o logs del test privado. No se proyecta excepción ni log-tail. Los shell anteriores ya devuelven STOP fijo sin red. La receta de publisher real ya captura build en su propio log; el wrapper también cubre sus errores anteriores a esa redirección.
- **Rollback de bytes ajenos:** las funciones de reemplazo/restore ahora registran hash, modo, inodo y dispositivo, usan no-follow, temporal/fsync, comparan dos veces antes de reemplazo y solo restauran identidad propia. Preview residual detectado en SHA2a458 (env write fallaba antes de escribir y se reiniciaba con env ajeno) está cerrado en a7bef: si no llegó a escribirse, exige identidad original exacta; si se escribió, restore-owned; ambos se releen antes de reiniciar. Drift ⇒ STOP_NEEDS_OPERATOR sin restart. Drop-in solo se elimina con cuerpo/metadatos propios. Son guardas de detección/revisión, no un CAS universal contra todo escritor externo entre último check y rename.
- **Builder tras timeout:** cerrado en a7bef. `builder_quiescent()` requiere consulta Docker exit0 y ausencia de contenedores candidato/canónico, incorporada al estado de publisher y antes/después del test, cortes y reanudación. Timeout del bash puede dejar Docker activo: devuelve STOP y no reanuda watcher mientras siga ese residuo; no mata recursos ajenos ni presume limpieza.
- **Selectores por substring:** cerrado inicialmente con shlex y cardinalidad/valor exactos; el delta final elimina la consulta Environment y prueba el cuerpo/hash propio del único drop-in permitido junto a la unidad literal. Sufijo/path distinto/otro drop-in da STOP, no un falso seleccionado.
- **RO cambiaba fuente tras validar hash:** cerrado en de99. Lee base/payload una sola vez, compara esos buffers y envía su decodificación; no vuelve a abrirlos para ejecutar. Bootstrap de módulos y scripts remotos RAM elimina la dependencia del antiguo transporte de scripts en disco.
- **Source/site:** se conservan árboles antiguos458/53 y sus nombres/config/symlinks opacos. Staging valida tipos/rutas, límites, duplicate/path traversal y archivos regulares, compara55/232 byte a byte. Mueve a paths versionados; bind web y drop-in publisher apuntan al mismo sitio nuevo. El runner empaquetado964182 soporta SRC/SITE/image/store/bridge/PBURL y unidad ExecStart conocidos; ese contrato fue leído del archive literal, no inventado.
- **Secuencia:** pausar solo watcher con service/request/builders inactivos antes del test; test bridge/site/logs propios, source staged y PB público, cero request real consumido. Resultado0+ES/EN y recibo de source/runner; builder/store solos no cierran CMS. `resume-old-publisher` exige runtime/config/árboles viejos y unidad sin drop-in; `resume-publisher` exige selección nueva, runtime healthy y test.
